---

OpenSearch는 대규모 데이터셋을 효율적으로 검색하고 필터링할 수 있는 강력한 오픈소스 검색 및 분석 엔진입니다. 흔히 사용되는 검색 패턴 중 하나는 특정 필드 값이 대규모 집합 내의 값과 일치하는지 여부를 기준으로 문서를 필터링하는 것입니다. 기존의 `terms` 쿼리는 소규모 집합에는 잘 작동하지만, 수천 혹은 수백만 개의 term을 처리할 때 성능이 급격히 저하됩니다.

OpenSearch 2.17에서는 이 문제를 해결하기 위해 **비트맵 필터링(bitmap filtering)** 을 도입했습니다. 이는 대규모 필터링 작업을 더 효율적으로 처리하는 방법을 제공합니다. OpenSearch 2.19에서는 소규모 쿼리 성능을 개선하고 전반적인 효율성을 높이는 인덱스 기반 비트맵 쿼리로 이 기능을 한층 강화했습니다.

---

## 대규모 필터링의 과제

많은 애플리케이션에서 숫자 식별자가 대규모 집합의 값과 일치하는지를 기준으로 문서를 필터링해야 합니다. 다음과 같은 예시를 생각해볼 수 있습니다.

- 이커머스 플랫폼이 고객의 디지털 라이브러리에 있는 상품만 표시하기 위해 제품 카탈로그를 필터링하는 경우 (수천 개의 구매 상품 ID 목록과 제품 ID를 대조)
- 서점 체인이 특정 매장의 도서를 모두 검색하는 경우 (수천 개의 ISBN 목록과 도서 ID를 대조)

대규모 ID 집합에 `terms` 쿼리를 사용하면 다음과 같은 문제가 발생할 수 있습니다.

- 쿼리 크기가 증가할수록 성능 저하
- 높은 메모리 및 CPU 소비로 인한 확장성 한계
- 방대한 필터 목록 전송으로 인한 네트워크 오버헤드

이러한 한계는 특히 대용량 데이터셋과 고트래픽 워크로드에서 성능과 확장성 모두에 부정적인 영향을 미칩니다.

---

## 비트맵 필터링: 최적화된 접근 방식

비트맵 필터링은 제품 ID나 ISBN 번호와 같은 정수 집합으로 필터링할 때 쿼리 성능과 확장성을 향상시킵니다. 이 기능은 정수 집합을 효율적으로 처리하는 자료구조인 **RoaringBitmap**을 활용합니다.

- RoaringBitmap은 데이터 특성에 따라 가장 효율적인 내부 표현 방식을 자동으로 선택합니다. 희소한(sparse) 정수 집합에 대해 뛰어난 압축률을 제공하면서도 빠른 조회 속도를 유지합니다.
- 집합 연산(예: 교집합, 합집합)은 OpenSearch에 쿼리를 보내기 전에 RoaringBitmap 라이브러리를 사용해 클라이언트 측에서 효율적으로 계산할 수 있습니다.

### OpenSearch의 비트맵 필터링 구현 방식

OpenSearch는 비트맵 필터링을 기존 쿼리 인프라에 원활하게 통합합니다.

- `terms` 쿼리에 새로운 `value_type` 파라미터가 추가되어, Base64로 인코딩된 Roaring 비트맵을 사용한 필터 목록 지정이 가능합니다.
- terms lookup이 개선되어 전체 `_source`가 아닌 저장된 필드(stored fields)에서 값을 가져옵니다.

## 예시: 고객의 구매 상품 필터링

100만 개의 상품과 10만 명의 고객을 보유한 이커머스 마켓플레이스를 운영한다고 가정해봅시다. 각 고객은 자신이 구매한 상품을 담은 디지털 라이브러리를 갖고 있고, 각 고객의 상품 보유 현황을 나타내는 비트맵을 유지 관리합니다. 비트맵 필터링을 사용하면 특정 고객이 소유한 상품을 다음과 같이 효율적으로 조회할 수 있습니다.

```json
POST products/_search
{
  "query": {
    "terms": {
      "product_id": {
        "index": "customers",
        "id": "customer123",
        "path": "customer_filter",
        "store": true
      },
      "value_type": "bitmap"
    }
  }
}
```

이 예시에서 비트맵 필터는 `products` 인덱스의 `product_id` 필드에 적용되어 특정 고객이 소유한 상품을 조회합니다. 비트맵 필터 데이터는 `customers` 인덱스의 문서 ID `customer123` 아래 `customer_filter` 필드에 저장됩니다. 이 바이너리 필드는 빠른 검색과 효율적인 처리에 최적화되어 있습니다. 쿼리 실행 시 비트맵 필터가 메모리에 로드되어 필터링 작업에 적용됩니다.

terms lookup을 사용하는 방법 외에도, 쿼리에 비트맵을 직접 제공할 수도 있습니다.

```json
POST products/_search
{
  "query": {
    "terms": {
      "product_id": ["<base64로 인코딩된 비트맵>"],
      "value_type": "bitmap"
    }
  }
}
```

이 경우 쿼리에 포함하기 전에 비트맵을 Base64로 인코딩해야 합니다. 이 방식은 미리 계산된 비트맵이 있거나 OpenSearch에 쿼리를 보내기 전에 클라이언트 측에서 비트맵 연산을 수행해야 할 때 유용합니다.

## 비트맵 필터링의 주요 장점

비트맵 필터링은 OpenSearch의 기존 쿼리 인프라와 원활하게 통합됩니다.

- `value_type: "bitmap"` 파라미터를 통해 `terms` 쿼리에서 비트맵 필터를 지정할 수 있습니다.
- 향상된 terms lookup으로 저장된 비트맵 필터를 효율적으로 검색할 수 있습니다.
- 비트맵 필터를 Boolean 쿼리 내 다른 쿼리 타입과 조합할 수 있어, 대규모 필터링을 위한 유연한 도구가 됩니다.

이러한 개선으로 기존 OpenSearch 쿼리에 최소한의 변경만 가하면서도 대규모 필터링 작업에서 상당한 성능 향상을 얻을 수 있습니다.

---

## 성능 벤치마크

1억 개의 문서를 포함하는 인덱스에서, 100개에서 1,000만 개에 이르는 다양한 필터 크기의 무작위 ID를 대상으로 여러 필터링 방식의 성능 테스트를 수행했습니다.

비교 대상은 다음과 같습니다.

1. doc-values 전용 필드에서 ID 목록을 사용하는 쿼리 (표준 terms 쿼리, OpenSearch 2.17)
2. 인덱스 필드에서 ID 목록을 사용하는 쿼리 (표준 terms 쿼리, OpenSearch 2.17)
3. doc-values 전용 필드에서 비트맵 필터링을 사용하는 쿼리 (OpenSearch 2.17)
4. 인덱스 필드에서 비트맵 필터링을 사용하는 쿼리 (OpenSearch 2.19)

필터 크기가 100,000개 이하일 때는 표준 방식과 비트맵 방식의 성능이 비슷했습니다. 하지만 더 큰 필터 크기에서는 표준 방식의 성능이 급격히 저하된 반면, 비트맵 필터링은 수백만 개의 ID에서도 안정적인 성능을 유지했습니다.

### 최적화된 비트맵 필터링 비교

OpenSearch 2.19에서는 인덱스 기반 비트맵 쿼리가 도입되었습니다. 이제 비트맵 쿼리는 Boolean 쿼리 내에서 다른 필터와 함께 사용될 때 쿼리 컨텍스트와 비용 추정을 기반으로 인덱스 쿼리와 doc value 쿼리 중 가장 효율적인 실행 전략을 자동으로 선택합니다.

기존 doc-value 기반 비트맵 구현과 비교했을 때, 새 구현은 벤치마크 실험에서 놀라운 성능 향상을 보여줍니다.

- 소규모 필터 크기에서 **1,000배 속도 향상**
- 수백만 개의 ID에서도 지속적으로 낮은 쿼리 시간 유지
- 모든 필터 크기에 걸쳐 안정적인 성능

### 공간 효율성

비트맵 필터링은 속도뿐만 아니라 공간 효율성도 뛰어납니다. 1,000만 개의 ID를 포함하는 필터를 비트맵으로 인코딩하면 **16MB**의 저장 공간만 필요한 반면, 원시 ID 목록으로는 **360MB**가 필요합니다. 이 압축된 표현 방식은 네트워크 전송 시간, 디스크 I/O, 메모리 사용량을 모두 줄여줍니다.

---

## 결론

OpenSearch의 비트맵 필터링은 수천에서 수백만 개에 이르는 대규모 숫자 식별자 집합으로 문서를 필터링하는 효율적인 방법을 제공합니다. `terms` 쿼리 및 terms lookup과 통합되어 있어 다음과 같은 시나리오에 특히 유용합니다.

- 사용자 권한에 따라 대규모 문서 컬렉션을 필터링하는 디지털 콘텐츠 플랫폼
- 고객 라이브러리와 제품 ID를 대조하는 이커머스 플랫폼

비트맵 필터링과 표준 terms 쿼리 중 어느 것이 더 적합한지 판단하려면 성능 벤치마크를 참고하세요. 대규모 애플리케이션에서 비트맵 필터링을 사용하고 있다면, [OpenSearch 포럼](https://forum.opensearch.org/)에 피드백을 남겨 향후 개선에 기여해주세요.
